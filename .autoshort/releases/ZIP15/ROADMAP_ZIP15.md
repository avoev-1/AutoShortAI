# ROADMAP ZIP15 — Guardian Engine Foundation

## Release Goal

Create the architecture foundation for an independent Guardian Engine that protects AutoShortAI before the next heavy ZIPs and before large-scale Claude implementation.

## Phase 1 — Foundation

- Define Guardian core models.
- Define rule and check protocols.
- Define reports and violations.
- Define severity and scope models.
- Add rule-pack templates.

## Phase 2 — Architecture Protection

- Add architecture integrity check contracts.
- Add module boundary rule contracts.
- Add ZIP compatibility guard contracts.
- Add platform/provider neutrality checks.
- Add lightweight/performance checks.

## Phase 3 — Restricted Workflow Protection

- Add restricted / adult creator mode guard contracts.
- Validate opt-in and isolation requirements.
- Validate maturity rating and consent metadata requirements.
- Validate manual review defaults.
- Validate restricted logs/assets/credentials readiness.

## Phase 4 — Reporting

- Add JSON/Markdown report templates.
- Add score models.
- Add violation output format.
- Add examples for Claude implementation review.

## Future Work

- ZIP16 should use Guardian rules to protect multi-platform publishing.
- ZIP17 should use Guardian rules to protect workspace/media boundaries.
- ZIP18 should expand security/secrets checks into a real vault architecture.
- ZIP19 should use Guardian rules for packaging compatibility.
- ZIP20 should stabilize Guardian as part of release governance.
